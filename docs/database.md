# Схема данных — AI Personal Chef

## Общая архитектура приложения
Приложение использует **гибридное хранение данных**:
- **Сервер** — общие AI-рецепты (общие для всех пользователей).
- **Клиент (устройство пользователя)** — персональные данные: сохранённые рецепты, оценки, собственные рецепты, настройки.

Даная структура была выбрана для снижения нагрузки на сервер и упрощения масштабирования.

---

## Сервер (`database/schema.sql`)

### Таблица: `recipes`
Хранит AI-сгенерированные и официальные рецепты.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER | Уникальный ID рецепта |
| `title` | TEXT | Название |
| `ingredients` | TEXT | JSON-массив ингредиентов |
| `steps` | TEXT | JSON-массив шагов |
| `cooking_time` | INTEGER | Время приготовления (мин) |
| `calories` | INTEGER | Калорийность |
| `difficulty` | TEXT | 'easy', 'medium', 'hard' |
| `source` | TEXT | 'ai' или 'official' |
| `created_at` | DATETIME | Время создания |

---

## Клиент (БД на устройстве пользователя)

Хранятся в **локальной БД приложения**.  
Структура представлена ниже как **логическая модель** для разработки.

### Таблица: `user_profile`
Профиль и настройки пользователя.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER | Всегда 1 (один профиль на устройство) |
| `name` | TEXT | Имя (опционально) |
| `phone` | TEXT | Телефон (опционально) |
| `theme` | TEXT | 'light', 'dark', 'auto' |
| `diet_tags` | TEXT | JSON: ["vegan", "gluten-free"] |
| `allergies` | TEXT | JSON: ["nuts", "dairy"] |
| `created_at` | DATETIME | Время первого запуска |


---

### Таблица: `saved_recipes`
Собственные и сохраненные рецепты пользователя.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | TEXT | UUID или "local-1", "local-2" |
| `type` | TEXT | 'ai' или 'manual' |
| `title` | TEXT | Название |
| `ingredients` | TEXT | JSON |
| `steps` | TEXT | JSON |
| `cooking_time` | INTEGER | Минуты |
| `calories` | INTEGER | Калории |
| `rating` | INTEGER | 1–5 |
| `notes` | TEXT | Заметки |
| `created_at` | DATETIME | Время создания |
| `updated_at` | DATETIME | Время изменения |

## ER-диаграмма


![Use-case диаграмма: Подбор рецепта по продуктам](/docs\images\er-diagram.png)

Диаграмма содержит три независимые сущности:
- `recipes` — общие рецепты (сервер)
- `user_profile` — настройки пользователя (локально)
- `user_recipes` — персональные рецепты (локально)

Связи между таблицами отсутствуют, потому что:
- Все данные рецепта (включая ингредиенты и шаги) хранятся внутри одной записи как JSON.
- Локальные рецепты — это полные копии, а не ссылки на серверные.
- Профиль пользователя не связан с рецептами напрямую (данные привязаны к устройству, а не к аккаунту).

## Работоспособность

- Пользователь сканирует продукты → запрос к серверу → получает список `recipes`.  
- Сохраняет рецепт → запись в `saved_recipes` (локально).  
- Создаёт свой рецепт → запись в `saved_recipes` (локально).  
- Все действия — **без передачи личных данных на сервер**.
